# 第四阶段说明

第四阶段名称：课程资料与知识库基础。

本阶段目标是让 EduForge 具备最小可演示的课程知识库链路：原创课程资料、文档解析、文本分块、SQLite 入库、关键词检索和来源展示。它为后续 RAG、智能辅导、防幻觉引用来源打基础，但本阶段不实现真正 RAG。

## 第四阶段目标

- 为《数据库系统》构造完整原创示例课程资料。
- 支持导入示例课程资料。
- 支持上传 Markdown / TXT 课程资料。
- 实现文档解析。
- 实现文本分块。
- 将文档和 chunk 存入 SQLite。
- 实现基础关键词检索。
- 前端新增 `/knowledge-base` 页面。
- 能搜索“幻读”“B+树”“JOIN”，并展示来源文件和 chunk。

## 为什么先做解析和分块

RAG 的关键不只是把大模型接进来，而是先保证资料来源可靠、文本能被稳定解析、分块粒度合适、检索结果能追溯到原文位置。先做解析和分块，可以让团队看清楚数据链路，也方便后续评估向量检索、重排、防幻觉引用和智能辅导的效果。

## 示例课程资料说明

示例资料位于：

```text
data/sample_courses/database_system/
```

包含 10 个原创 Markdown 文件，覆盖数据库基础、关系模型、SQL、JOIN、ER 建模、范式、事务、索引、查询优化和综合复习。

这些资料为项目团队原创整理内容，不包含出版教材 PDF、扫描件、教材原文或出版社配套资料。

## 数据模型说明

### CourseDocument

保存课程文档元数据，包括课程、文件名、原始文件名、文件类型、来源类型、存储路径、索引状态、chunk 数、错误信息和内容 hash。

### DocumentChunk

保存文档分块内容，包括文档 id、课程 id、chunk 序号、章节标题、内容、字符数、内容 hash 和 metadata_json。

第四阶段不保存 embedding，不保存 vector。

## 文档导入流程

```text
示例资料 → 解析 → 分块 → 入库
```

上传资料流程同样会经过解析、分块和入库。重复导入同一个示例资料时，会通过 course_id、original_filename 和 content_hash 跳过重复文档。

## 支持的文件类型

- `.md`
- `.txt`

## 暂不支持

- PDF
- Word
- PPTX
- OCR
- 视频

## API 列表

- `GET /api/courses/{course_id}/documents`
- `POST /api/courses/{course_id}/documents/import-sample`
- `POST /api/courses/{course_id}/documents/upload`
- `GET /api/courses/{course_id}/documents/{document_id}/chunks`
- `GET /api/courses/{course_id}/knowledge-base/stats`
- `GET /api/courses/{course_id}/knowledge-base/search?q=幻读&limit=10`

## 前端页面

`/knowledge-base` 页面提供：

- 课程选择
- 知识库统计
- 导入《数据库系统》示例资料
- 上传 `.md` / `.txt`
- 文档列表
- chunk 查看
- 关键词搜索
- “幻读”“B+树”“JOIN”快捷搜索

后端关闭时页面会显示错误提示，不白屏。

## 搜索功能说明

第四阶段使用基础关键词检索，不使用 embedding 和 ChromaDB。检索分数由完整 query 命中、简单 token 命中和标题命中加权得到，按 score 降序返回来源文件、chunk 序号、章节标题、内容和 metadata_json。

## 本阶段没有实现

- embedding
- RAG

- 智能辅导
- 学习画像生成
- 学习路径生成

- 测验批改
- 登录
- Docker
- Alembic
