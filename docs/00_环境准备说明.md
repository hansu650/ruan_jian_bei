# 环境准备说明

本文档面向 EduForge 智学工坊团队成员，用于统一本地开发环境、启动方式和常见问题处理。当前项目处于第四阶段：课程资料与知识库基础。

## 为什么使用 Conda

中国软件杯项目通常会在多台电脑之间迁移和演示，Conda 可以稳定管理 Python 版本和隔离依赖，减少系统 Python、旧项目环境和比赛项目环境之间的冲突。本项目统一使用 Conda 管理后端运行环境，再使用 pip 安装项目依赖。

## 环境名

统一环境名为：

```bash
cnsoftbei_a3_eduforge
```

环境名包含比赛、赛题和项目含义，方便团队成员识别，避免误用其他历史环境。

## Python 版本

后端使用 Python 3.11。该版本兼容 FastAPI、Pydantic v2、SQLModel、pytest、ruff 和 mypy，适合比赛项目快速迭代与本地演示。

## 可编辑安装

后端支持：

```bash
cd apps/api
pip install -e .
```

`pip install -e .` 会以可编辑模式安装后端包，本地修改 `apps/api/app/` 下代码后不需要重复安装，测试和开发服务器可以直接识别最新代码。

## 前端环境

前端位于 `apps/web`，使用 Next.js、TypeScript、Tailwind CSS 和 shadcn/ui。要求：

- Node.js >= 20.9
- pnpm
- 推荐使用 Node.js LTS

安装 pnpm：

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

安装前端依赖：

```bash
cd apps/web
pnpm install
```

启动前端：

```bash
pnpm dev
```

默认访问 [http://localhost:3000](http://localhost:3000)。

## 数据库环境

第三阶段使用 SQLite + SQLModel：

- SQLite 不需要额外数据库服务，适合本地开发和比赛演示。
- SQLModel 与 FastAPI/Pydantic 结合简单，适合当前阶段的最小 CRUD。
- 默认数据库地址为 `sqlite:///./eduforge.db`。
- 按当前启动方式，数据库文件会生成在 `apps/api/eduforge.db`。
- 数据库文件已被 `.gitignore` 忽略，不要提交到仓库。

本阶段不使用 Alembic，不引入 PostgreSQL，不配置 Docker。

## 第四阶段知识库环境

第四阶段新增 `python-multipart`，用于 FastAPI 接收 Markdown / TXT 文件上传。当前只支持：

- `.md`
- `.txt`

暂不支持 PDF、Word、PPTX、OCR 和视频解析，也不安装 pypdf、python-docx、python-pptx、unstructured 等重型依赖。

示例课程资料位于：

```text
data/sample_courses/database_system/
```

这些资料为团队原创整理内容，会提交到 Git。上传文件保存到：

```text
apps/api/storage/uploads/
```

上传目录是本地运行产物，不提交 Git。

## Windows 环境准备

在项目根目录执行：

```powershell
conda create -n cnsoftbei_a3_eduforge python=3.11 -y
conda activate cnsoftbei_a3_eduforge

cd apps/api
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -r requirements-dev.txt
pip install -e .

cd ../..
cd apps/web
pnpm install
cd ../..

python scripts/check-env.py
```

也可以使用脚本：

```powershell
.\scripts\setup-conda.ps1
conda activate cnsoftbei_a3_eduforge
python scripts/check-env.py
```

## macOS/Linux 环境准备

在项目根目录执行：

conda create -n cnsoftbei_a3_eduforge python=3.11 -y

cd apps/api

./scripts/setup-conda.sh

## 启动方式

后端：

```bash
conda activate cnsoftbei_a3_eduforge
cd apps/api
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

前端：

```bash
cd apps/web
pnpm dev
```

脚本方式：

```powershell
.\scripts\run-api-dev.ps1
.\scripts\run-web-dev.ps1
```

macOS/Linux：

```bash
./scripts/run-api-dev.sh
./scripts/run-web-dev.sh
```

## 前后端联调

后端默认运行在 `http://localhost:8000`，前端默认运行在 `http://localhost:3000`。前端通过 `NEXT_PUBLIC_API_BASE_URL` 直接请求后端。

后端 CORS 允许：

- `http://localhost:3000`
- `http://127.0.0.1:3000`

第三阶段已为 CRUD 预留 `GET/POST/PUT/PATCH/DELETE/OPTIONS` 方法，但当前只实现 GET 和 POST。

## 常见问题

### conda 不是内部或外部命令

说明系统找不到 Conda。请安装 Anaconda 或 Miniconda，并确认 PATH 配置正确。Windows 上也可以使用 Anaconda Prompt。

### conda activate 失败

PowerShell 可执行：

```powershell
conda init powershell
```

然后重新打开 PowerShell。macOS/Linux 可执行：

```bash
conda init bash
```

如果使用 zsh：

```bash
conda init zsh
```

### PowerShell 执行策略问题

如果运行 `.ps1` 脚本时报执行策略错误，可执行：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### pip install 失败

先确认环境已激活：

```bash
conda activate cnsoftbei_a3_eduforge
python --version
python -m pip --version
```

再升级 pip：

```bash
python -m pip install --upgrade pip
```

网络不稳定时可稍后重试。

### FastAPI 无法导入

说明后端依赖未安装或当前终端没有激活正确环境：

```bash
conda activate cnsoftbei_a3_eduforge
cd apps/api
pip install -r requirements.txt
pip install -e .
```

### SQLModel 无法导入

第三阶段新增了 `sqlmodel>=0.0.22`。请重新安装后端依赖：

```bash
conda activate cnsoftbei_a3_eduforge
cd apps/api
pip install -r requirements.txt
```

### uvicorn 命令不存在

请确认依赖已安装：

```bash
conda activate cnsoftbei_a3_eduforge
cd apps/api
pip install -r requirements.txt
```

也可以使用：

```bash
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 端口 8000 被占用

可以临时切换端口：

```bash
cd apps/api
uvicorn app.main:app --reload --host 0.0.0.0 --port 8001
```

同时需要把前端环境变量里的后端地址改到 `http://localhost:8001`。

### Node 版本过低

前端要求 Node.js >= 20.9。请安装 Node.js LTS，或使用 nvm/fnm 切换版本。

### pnpm 未安装

执行：

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

第三阶段已经有正式前端项目，pnpm 缺失会导致自检失败。

### 前端无法访问后端

确认后端已启动，并检查：

- 后端是否在 `http://localhost:8000`
- `apps/web/.env.local` 或 `.env.example` 中的 `NEXT_PUBLIC_API_BASE_URL`
- 浏览器控制台是否有 CORS 报错

### 数据库文件没有出现

`apps/api/eduforge.db` 会在后端启动并执行 lifespan 初始化后生成。只运行 `python scripts/check-env.py` 不一定会创建数据库。数据库文件不提交 Git。

## 环境重建

如果环境损坏，可删除并重建 Conda 环境：

```bash
conda deactivate
conda remove -n cnsoftbei_a3_eduforge --all
conda create -n cnsoftbei_a3_eduforge python=3.11 -y
conda activate cnsoftbei_a3_eduforge
cd apps/api
pip install -r requirements.txt
pip install -r requirements-dev.txt
pip install -e .
```

前端依赖可重装：

```bash
cd apps/web
pnpm install
```
