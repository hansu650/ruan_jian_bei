# 环境准备说明

本文档面向 EduForge 智学工坊团队成员，用于统一第一阶段开发环境。

## 为什么使用 Conda

比赛项目通常会经历多人协作、演示机器迁移、依赖升级和模型相关实验。Conda 能稳定管理 Python 版本和隔离环境，减少不同电脑之间的依赖冲突。第一阶段先使用 Conda 管理 Python 3.11，再使用 pip 安装项目依赖，既清晰又方便复现。

## 为什么环境名叫 cnsoftbei_a3_eduforge

环境名统一为 `cnsoftbei_a3_eduforge`，包含比赛、赛题和项目名称信息。这样团队成员在多项目、多环境切换时能快速识别当前环境，避免误用旧环境。

## 为什么 Python 用 3.11

Python 3.11 兼容 FastAPI、Pydantic v2、pytest、ruff、mypy 等现代 Python 工具链，同时性能和生态稳定性较好。比赛开发中使用 3.11 能兼顾新特性与部署可靠性。

## 为什么后端使用 pip install -e .

`pip install -e .` 表示以可编辑模式安装后端项目。安装后，本地修改 `apps/api/app/` 下的代码无需重新安装即可生效，测试和开发服务器都能直接识别包路径。它适合比赛项目的快速迭代，也方便后续拆分 routers、services、agents 等模块。

## 为什么 Node.js 要 >= 20.9

后续前端计划使用 Next.js、TypeScript、Tailwind CSS 和 shadcn/ui。较新的 Next.js 生态对 Node.js 版本有要求，使用 Node.js >= 20.9 可以减少构建和依赖安装问题。推荐直接使用 Node.js LTS。

## 为什么第一阶段不急着创建前端项目

第一阶段目标是环境准备和工程规范初始化。此时创建 Next.js 项目会引入大量前端依赖、锁文件和配置，容易分散注意力。先稳定后端环境、自检脚本、目录结构和文档，第二阶段再创建正式前端骨架会更稳。

## Docker 什么时候配置

Docker 建议放到后续阶段配置。第一阶段只把 Docker 作为可选工具检查，缺失时只给出 WARN。等后端 API、前端骨架、数据库或知识库目录、统一启动方式稳定后，再补充 `Dockerfile` 和 `docker-compose.yml`，这样更适合比赛项目快速迭代。

## Windows 环境准备步骤

在项目根目录执行：

```powershell
conda create -n cnsoftbei_a3_eduforge python=3.11 -y
conda activate cnsoftbei_a3_eduforge

cd apps/api
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -r requirements-dev.txt
pip install -e .

cd ../..
python scripts/check-env.py
```

也可以使用一键脚本：

```powershell
.\scripts\setup-conda.ps1
conda activate cnsoftbei_a3_eduforge
python scripts/check-env.py
```

## 常见问题

### conda 不是内部或外部命令

说明系统找不到 Conda。请先安装 Anaconda 或 Miniconda，并确认安装时勾选或手动配置了 PATH。Windows 上也可以使用 Anaconda Prompt 执行命令。

### conda activate 失败

可能是当前终端没有初始化 Conda。可尝试：

```powershell
conda init powershell
```

然后重新打开 PowerShell。macOS/Linux 可尝试：

```bash
conda init bash
```

如果使用 zsh，则执行：

```bash
conda init zsh
```

### PowerShell 执行策略问题

如果运行 `.ps1` 脚本时报执行策略错误，可以在当前用户范围调整：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

调整后重新打开 PowerShell 再运行脚本。

### pip install 失败

先确认已经激活环境：

```bash
conda activate cnsoftbei_a3_eduforge
python --version
python -m pip --version
```

然后升级 pip：

```bash
python -m pip install --upgrade pip
```

如果网络不稳定，可切换稳定网络后重试。

### FastAPI 无法导入

说明后端依赖未安装或当前终端没有激活正确环境。请执行：

```bash
conda activate cnsoftbei_a3_eduforge
cd apps/api
pip install -r requirements.txt
pip install -e .
```

### uvicorn 命令不存在

说明后端运行依赖未安装或 PATH 未指向当前环境。请执行：

```bash
conda activate cnsoftbei_a3_eduforge
cd apps/api
pip install -r requirements.txt
```

也可以用 Python 模块方式验证：

```bash
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 端口 8000 被占用

可以临时换端口：

```bash
cd apps/api
uvicorn app.main:app --reload --host 0.0.0.0 --port 8001
```

然后访问 `http://localhost:8001/api/health`。

### node 版本过低

后续前端需要 Node.js >= 20.9。请安装 Node.js LTS，或使用 nvm / fnm 等工具切换版本。

### pnpm 未安装

第一阶段尚未创建前端项目，pnpm 缺失不会阻塞后端验证。后续需要前端开发时执行：

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

## 环境重建方法

如果环境损坏，可以删除并重建 Conda 环境。删除前请确认没有重要内容只保存在环境目录中：

```bash
conda deactivate
conda remove -n cnsoftbei_a3_eduforge --all
conda create -n cnsoftbei_a3_eduforge python=3.11 -y
conda activate cnsoftbei_a3_eduforge
cd apps/api
pip install -r requirements.txt
pip install -r requirements-dev.txt
pip install -e .
```

## 如何确认环境成功

1. 自检通过：

```bash
python scripts/check-env.py
```

2. 测试通过：

```bash
cd apps/api
pytest
```

3. 启动服务：

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

4. 浏览器访问：

- [http://localhost:8000/api/health](http://localhost:8000/api/health)
- [http://localhost:8000/docs](http://localhost:8000/docs)
