# Phase 15B：全局 UI 重构与创新点包装

## 1. 本阶段目标

Phase 15B 不新增后端大功能、不新增 Agent、不修改 SparkHTTPProvider，也不触发真实模型生成。本阶段重点是把 EduForge 从“功能完整但偏控制台”的状态，进一步打磨成更像正式学习产品的前端体验。

主要目标：

- 让首页和 `/learn` 更像学生每天进入的学习平台。
- 统一导航、卡片、按钮、指标和状态标签。
- 优化 `/resources`、`/tutor`、`/practice`、`/analytics` 的学习产品表达。
- 强化 `/agents-flow` 多智能体协作视图。
- 强化 `/innovation` 创新亮点页。
- 保持简约、可信、低噪音的视觉风格。

## 2. 为什么要做 UI 产品化重构

前面的阶段已经完成画像、路径、资源、答疑、测验和评估等核心功能。比赛演示时，评委和学生首先看到的是产品外壳，如果页面像后台或调试台，会削弱功能完成度的观感。

Phase 15B 的重点不是继续堆功能，而是让系统更容易被理解：

- 学生能看懂“今天该学什么”。
- 评委能看懂“多智能体如何协作”。
- 页面能体现“学习闭环”，而不是多个孤立功能点。
- 资源、答疑和评估结果更像学习资料与学习诊断。

## 3. 参考开源项目的原则

本阶段可以参考开源 dashboard、学习平台和 AI 学习助手项目的设计思路，但遵守以下原则：

- 只借鉴布局结构、信息层级、导航分组、卡片组织和表达方式。
- 不复制其他项目代码文件。
- 不复制其他项目文案、Logo、图片或视觉资产。
- 不把未实现能力包装成已实现功能。
- 不引入重型依赖，不改变当前 Next.js + Tailwind + shadcn/ui 体系。

## 4. `/learn` 学生端学习首页

`/learn` 继续作为学生端第一入口。本阶段强化了这些信息：

- 当前学生、当前课程、学习目标和学习状态。
- 今日推荐学习任务。
- 学习画像、学习路径、学习资料、练习结果的概览。
- 薄弱点与优先学习建议。
- 从画像到评估的学习旅程。

这些信息来自后端数据库和 API，不依赖本地临时状态。

## 5. `/agents-flow` 多智能体协作视图

`/agents-flow` 用于解释项目真实实现的轻量多智能体流水线：

- ProfileAgent：学习画像。
- PlannerAgent：学习路径。
- ResourceAgent：学习资源。
- TutorAgent：智能辅导。
- PracticeAgent：练习生成。
- EvaluatorAgent：自动批改与评估。
- CitationVerifier：引用与版权风险校验。

页面只声明“自研轻量多智能体流水线”，不宣称接入 CrewAI、LangGraph 或复杂调度平台。

## 6. `/innovation` 创新亮点页

`/innovation` 将真实已有能力包装成评委容易理解的创新点：

- 画像驱动的个性化学习闭环。
- 可信课程知识库与引用来源。
- 多智能体学习流水线。
- 六类个性化学习资源生成。
- 轻量掌握度追踪与学习效果评估。
- Mock / Spark 双模式。
- 引用来源防幻觉与版权边界。

## 7. UI 风格收敛说明

本阶段继续采用低饱和蓝和中性灰：

- 页面背景以浅灰和白色为主。
- 卡片使用细边框、轻阴影、统一圆角。
- 状态标签统一中文化。
- 学生页面减少 Agent、API、Phase 等工程词。
- 演示、测试、模型实验室等工程入口保留，但降级为辅助入口。

## 8. 真实已实现的创新点

可以在答辩中说明的能力包括：

- 8 维学习画像。
- 个性化学习路径。
- 六类学习资源生成。
- 课程知识库分块检索。
- citations_json 引用来源。
- TutorAgent 带来源答疑。
- PracticeAgent 多题型测验。
- EvaluatorAgent 自动批改、错因分析、掌握度更新。
- MockLLM 与 Spark HTTP Provider 双模式。

## 9. 仅作为后续扩展的能力

以下能力不能写成已实现：

- 完整 BKT 算法。
- 费曼学习法。
- 情感识别。
- 多 Agent 辩论。
- 成就系统。
- 知识图谱可视化。
- CrewAI / LangGraph 调度平台。
- 真实流式输出。

可以在后续规划中写成“可扩展方向”，但不能在当前成果中虚假宣传。

## 10. 验收方式

自动化检查：

```powershell
.\scripts\check-phase15b.ps1
```

```bash
./scripts/check-phase15b.sh
```

手动检查：

1. `/` 像正式产品首页，主按钮进入 `/learn`。
2. `/learn` 有今日任务、学习进度、薄弱点和继续学习入口。
3. `/resources` 资源卡片像学习资料，Markdown / Mermaid 渲染正常，默认不全选 6 类资源。
4. `/tutor` 回答和引用来源清楚，可信状态中文化。
5. `/practice` 批改反馈包含得分、准确率、错因、掌握度和补救建议。
6. `/analytics` 更像学习诊断报告。
7. `/agents-flow` 能解释多个 Agent 的协作链路。
8. `/innovation` 只包装真实能力，不虚构未实现功能。
9. 页面、文档和日志中不出现真实密钥。
10. 自动化测试不真实调用 Spark。
