# 第五阶段说明

第五阶段名称：MockLLM 与讯飞接口预留。

本阶段目标是建立统一 LLMProvider 抽象、离线 MockLLMProvider、SparkProvider 预留、Prompt 模板、LLM 调用日志和前端模型实验室。它为第六阶段 ProfileAgent 做准备，但本阶段不实现任何正式 Agent。

## 第五阶段目标

- 建立统一 LLMProvider 抽象接口。
- 实现 MockLLMProvider。
- 预留 SparkProvider。
- 实现 LLM status / scenarios / generate / chat / logs API。
- 创建基础 Prompt 模板目录。
- 记录 LLMCallLog。
- 新增 `/llm-lab` 页面。

## 为什么先做 MockLLM 和 Provider 抽象

直接写 Agent 容易把模型调用、Prompt、业务流程、日志和错误处理混在一起。先做 Provider 抽象，可以让后续 ProfileAgent、PlannerAgent、ResourceAgent 等模块统一调用模型能力。MockLLM 能让团队在没有真实 Key 的情况下先完成演示链路、接口测试和前端交互。

## 为什么当前不接真实 API

- 还没有进入 A3 答疑群确认真实模型要求。
- 避免产生接口费用。
- 避免过早绑定错误供应商或错误协议。
- 保证没有 API Key 也能完整演示。
- 避免把真实密钥带入日志、测试或文档。

## Provider 架构

### MockLLMProvider

离线演示模型，不调用任何外部 API。它根据场景返回稳定内容，便于测试：

- `profile` 返回可解析 JSON。
- `learning_path` 返回可解析 JSON。
- `resource_note` 返回 Markdown。
- `quiz` 返回可解析 JSON。
- `tutor` 返回带模拟引用来源的答疑。
- `safety_check` 返回安全检查 JSON。

Mock 输出适合演示和测试，不代表真实大模型效果。

### SparkProvider 预留

SparkProvider 为科大讯飞相关工具接入预留接口。当前不会调用讯飞星火真实 API，也不引入 SDK。后续根据 A3 答疑群要求再实现。

## 环境变量

```env
USE_MOCK_LLM=true
LLM_PROVIDER=mock
LLM_MODEL=mock-edu-model
LLM_TIMEOUT_SECONDS=60

SPARK_APP_ID=
SPARK_API_KEY=
SPARK_API_SECRET=
SPARK_MODEL=
```

`USE_MOCK_LLM=true` 是默认值。Spark Key 为空不影响演示。

## LLMCallLog

`LLMCallLog` 记录 provider、model、scenario、prompt_preview、response_preview、status、error_message、latency_ms 和 created_at。

日志只保存前 500 字预览，不保存完整超长输入，不保存 API Key。

## /llm-lab 页面

模型实验室支持：

- 查看 provider 状态。
- 查看场景列表。
- 输入 Prompt 并调用 Generate。
- 输入 Chat 消息并调用 Chat。
- 查看最近调用日志。
- 明确提示当前不接真实 API、不需要 API Key、不产生费用。

## API 列表

- `GET /api/llm/status`
- `GET /api/llm/scenarios`
- `POST /api/llm/generate`
- `POST /api/llm/chat`
- `GET /api/llm/logs`

## 本阶段没有实现

- ProfileAgent
- 多智能体
- 学习路径规划
- 资源生成
- 智能辅导
- 测验批改
- RAG
- embedding

## 版权边界

- 不使用教材 PDF。
- 不要求模型复制教材原文。
- 示例资料为团队原创整理内容。
- MockLLM 遇到“复制教材原文”等请求会提示只能使用合法资料或原创整理内容。

5. 使用 Chat 测试答疑。
6. 查看 LLM 调用日志。
