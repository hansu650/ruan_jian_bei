# 第五阶段说明

第五阶段名称：MockLLM 与讯飞接口预留。

本阶段已经完成 LLMProvider 抽象、MockLLMProvider、SparkProvider 预留、Prompt 模板、LLMCallLog、`/api/llm/*` API 和前端 `/llm-lab` 页面。

## 为什么先做 MockLLM

在尚未进入 A3 答疑群确认真实模型要求前，项目不绑定任何真实供应商，不产生 API 费用，也不要求队友配置密钥。MockLLM 能让后续 ProfileAgent、PlannerAgent 和资源生成链路先完成接口、日志和页面演示。

## Provider 架构

- `MockLLMProvider`：离线固定输出，支持 profile、learning_path、resource_note、quiz、tutor、safety_check 等场景。
- `SparkProvider`：科大讯飞相关工具接入预留，目前不调用真实讯飞星火 API。

## API

- `GET /api/llm/status`
- `GET /api/llm/scenarios`
- `POST /api/llm/generate`
- `POST /api/llm/chat`
- `GET /api/llm/logs`

## 阶段边界

第五阶段没有实现真实 API 调用、OpenAI-compatible Provider、ProfileAgent、多智能体、学习路径规划、资源生成、智能辅导、测验批改、RAG 或 embedding。

## 第六阶段衔接

第六阶段在第五阶段的 MockLLM 和 LLMCallLog 基础上实现 ProfileAgent，但仍然不调用真实外部 API。
