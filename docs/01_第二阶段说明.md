# 第二阶段说明

## 阶段目标

第二阶段目标是完成前端骨架、后端基础工程结构整理、前后端 health check 联调和后续功能目录预留。该阶段强调可运行、可验收、不过度工程化。

## 前端页面

前端位于 `apps/web`，使用 Next.js App Router、TypeScript、Tailwind CSS 和 shadcn/ui 基础组件。

已创建页面：

- `/`：比赛演示风格首页，展示 EduForge、A3 赛题信息、核心闭环和后端健康状态。
- `/dashboard`：Dashboard 骨架页，展示当前课程、核心功能占位和阶段进度。
- `/health`：前后端联调页，展示前端状态、`/api/health` 和 `/api/meta` 返回结果。

## 后端结构

后端位于 `apps/api`，第二阶段整理为：

```text
app/
  core/
    config.py
  routers/
    health.py
    meta.py
  schemas/
    health.py
    meta.py
  main.py
```

`main.py` 只负责创建 app、配置 CORS 和注册路由。业务逻辑不放在 `main.py`。

当前接口：

- `GET /api/health`
- `GET /api/meta`

## 前后端联调方式

后端：

```bash
conda activate cnsoftbei_a3_eduforge
cd apps/api
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

前端：

```bash
cd apps/web
pnpm install
pnpm dev
```

访问：

- `http://localhost:3000`
- `http://localhost:3000/dashboard`
- `http://localhost:3000/health`
- `http://localhost:8000/api/health`
- `http://localhost:8000/api/meta`
- `http://localhost:8000/docs`

## 本阶段不实现

## 验收步骤

```bash

pytest

```

前端：

```bash
cd apps/web
pnpm lint
pnpm typecheck
pnpm build
pnpm dev
```

根目录：

```bash
python scripts/check-env.py
```

也可以运行：

```bash
./scripts/check-phase2.sh
```

```powershell
.\scripts\check-phase2.ps1
```

## 下一阶段计划

第三阶段建议进入数据库模型与基础 CRUD，但仍保持克制：先设计课程、知识点、学生、画像草稿、资源元数据等基础模型，再逐步接入真实业务流程。
