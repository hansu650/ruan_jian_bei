# Phase 13 端到端彩排与缺陷修复

## 1. Phase 13 目标

Phase 13 不新增业务 Agent，也不扩展模型能力，重点是围绕比赛演示做一次端到端彩排：检查前后端 API 命名、页面导航、Mock/Spark Lite 两种模式提示、空状态、错误提示和高消耗操作确认，修复低风险缺陷。

## 2. 为什么此阶段不做交付材料

PPT、视频脚本、系统开发说明书和测试说明书需要建立在稳定的演示链路之上。当前先完成彩排和缺陷修补，避免后续交付材料描述的流程与实际系统不一致。

## 3. 端到端人工彩排路线

1. 打开 `/demo`，检查 LLM 模式、演示状态和 bootstrap。
2. 打开 `/qa`，查看 Smoke Status 和人工测试清单。
3. 打开 `/knowledge-base`，搜索“幻读”“B+树”“JOIN”。
4. 打开 `/profile`，生成或查看 8 维学习画像。
5. 打开 `/learning-path`，生成或查看 7 天学习路径。
6. 打开 `/resources`，选择 step，生成单个资源或确认后一键生成 6 类资源。
7. 打开 `/tutor`，提问“幻读和不可重复读有什么区别？”并检查 citations。
8. 打开 `/practice`，生成测验、填写答案并提交。
9. 打开 `/analytics`，查看掌握度、薄弱点和评估报告。

## 4. Mock 模式和彩排说明

Mock 模式适合离线演示、自动化测试和录屏前快速彩排。该模式不会调用外部 API，不需要真实密钥，输出稳定，适合验证完整功能链路。

## 5. Spark Lite 模式和彩排说明

本地可以保持 `spark-http + lite` 配置进行真实小流量联调。`/demo`、`/qa`、`/api/demo/bootstrap` 和 `/api/qa/smoke-status` 不会自动调用模型；只有手动点击画像、路径、资源、辅导或测验生成类操作时才可能调用真实 API。

## 6. 高消耗操作注意事项

- `/resources` 一键生成 6 类资源可能连续触发多次模型调用，Spark Lite 模式下需要确认后再执行。
- `/practice` 生成测验会调用模型生成题目，建议先使用较小题量。
- `/tutor` 连续追问会产生多次调用，彩排时只需验证 1-2 个关键问题。
- 自动化测试和 check 脚本必须使用 Mock 或 mock 外部请求，不真实联网。

## 7. 真实密钥安全要求

- 不提交 `.env`。
- 不提交真实密钥。
- 不在前端输入、展示、传输或保存密钥。
- 不在日志、接口响应、README 示例、截图说明或测试 fixture 中输出真实密钥。
- 不把真实密钥粘贴到 Codex 提示词、GitHub issue 或聊天记录中。

## 8. 已检查的核心页面

- `/demo`：演示工作台和基础数据 bootstrap。
- `/qa`：Smoke Status 和人工测试清单。
- `/knowledge-base`：资料导入和关键词检索。
- `/profile`：对话式学习画像。
- `/learning-path`：个性化学习路径和薄弱点覆盖。
- `/resources`：多类型资源生成、citations 和高消耗操作确认。
- `/tutor`：智能辅导、引用来源和版权边界。
- `/practice`：练习生成、答题提交和自动批改。
- `/analytics`：学习效果评估、掌握度和报告。

## 9. 常见问题排查

- 没有课程资料：先进入 `/demo` 点击“准备基础演示数据”，或在 `/knowledge-base` 导入示例资料。
- 没有画像：进入 `/profile` 使用示例输入生成 8 维画像。
- 没有学习路径：先生成画像，再进入 `/learning-path` 生成 7 天路径。
- 资源无法生成：确认已有学习路径 step，并优先单独生成 `lecture_note`。
- Tutor 无 citations：确认知识库 chunk 已导入；无来源时系统会标记 `needs_review`。
- Spark JSON 返回格式不稳定：先在 `/llm-lab` 检查对应场景输出；业务侧仍保留 fallback。
- Evaluation fallback：简答题和 SQL 实操题采用轻量规则批改，不执行学生 SQL。

## 10. 下一阶段建议

Phase 13 之后已经进入学生端产品化打磨，建议优先处理：

- 学生主入口 `/learn` 是否能让首次使用者理解下一步。
- `/resources` 中 Markdown、SQL 代码块和 Mermaid 思维导图是否正常渲染。
- 顶部导航和侧边导航是否能清楚显示当前页面。
- 资源、辅导、练习和评估页面是否减少工程词，突出学习旅程。

最终交付材料仍建议放在学生端体验稳定之后再开始。
