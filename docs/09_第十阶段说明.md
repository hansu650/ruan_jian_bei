# 第十阶段说明：PracticeAgent + EvaluatorAgent 学习效果评估

## 1. 阶段目标

第十阶段实现 A3 赛题可选加分项“学习效果评估”：系统根据学习画像、学习路径、课程知识库和已生成资源生成练习测验，学生提交答案后自动批改，系统分析薄弱点、更新掌握度并推荐补救资源。

## 2. A3 题面对应

A3 要求系统能够跟踪练习测试情况、资源使用反馈等数据，并实现对学生学习效果的多维度评估。本阶段完成从“练习测验”到“批改反馈”再到“画像掌握度更新”的基础闭环。

## 3. PracticeAgent 设计

PracticeAgent 输入：

- Student
- Course
- LearnerProfile
- LearningPathStep
- DocumentChunk 检索片段
- GeneratedResource 辅助上下文

PracticeAgent 输出：

- PracticeQuiz
- PracticeQuestion 列表
- source_chunk_ids_json
- source_resource_ids_json

支持题型：

- `single_choice`
- `multiple_choice`
- `short_answer`
- `sql_practice`

题目为原创生成或模板生成，不复制教材原文。

## 4. EvaluatorAgent 设计

EvaluatorAgent 输入：

- PracticeQuiz
- PracticeQuestion
- 学生提交答案
- LearnerProfile.mastery_json

EvaluatorAgent 输出：

- PracticeAttempt
- PracticeAnswer
- weak_points
- strengths
- recommended_actions
- mastery_before_json
- mastery_after_json
- LearningEvaluationReport

## 5. 数据模型

- `PracticeQuiz`：一次练习测验。
- `PracticeQuestion`：测验题目，不在普通题目接口中暴露 `correct_answer_json`。
- `PracticeAttempt`：学生一次提交和批改结果。
- `PracticeAnswer`：逐题批改结果、得分和错因。
- `LearningEvaluationReport`：学习效果评估报告。

## 6. 练习生成流程

学习路径 step → PracticeAgent → MockLLM → fallback 题库 → 保存 Quiz 和 Questions。

如果 MockLLM 返回不可解析 JSON，系统会使用固定原创模板生成题目，保证无 API Key 也能演示。

## 7. 自动批改流程

学生提交答案 → EvaluatorAgent → 批改 → 错因分析 → 更新掌握度 → 生成 EvaluationReport。

批改规则：

- 单选题：严格匹配。
- 多选题：完全一致满分，部分命中给部分分。
- 简答题：按关键词覆盖程度评分。
- SQL 实操题：只检查 SQL 关键词，不执行 SQL。

## 8. 掌握度更新规则

- 正确率 >= 0.8：对应知识点掌握度 +8，最高 100。
- 正确率 >= 0.5 且 < 0.8：掌握度 +3。
- 正确率 < 0.5：掌握度 -5，最低 0。
- 不清空画像其他字段。
- LearnerProfile.version 自增。

## 9. 补救资源推荐

系统根据薄弱知识点生成补救建议，例如：

- 复习事务隔离级别图解讲义。
- 完成 B+ 树索引实操案例。
- 对 JOIN 错题进行二次练习。

本阶段只推荐补救方向，不自动重排学习路径。

## 10. 前端页面

### `/practice`

- 选择学生、课程、学习路径 step。
- 选择题型、难度和题目数量。
- 生成练习。
- 填写答案。
- 提交并展示批改结果、错因、掌握度变化。

### `/analytics`

- 展示 quiz_count、attempt_count、average_accuracy。
- 展示最新 mastery。
- 展示最新薄弱点和补救建议。
- 展示 LearningEvaluationReport 列表。

- 不复制教材原文。
- 不处理教材 PDF。
- 题目为原创生成或模板生成。
- 不输出出版社页码等未被引用支撑的来源。
