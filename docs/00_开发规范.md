# 开发规范

## 分支与提交

分支命名建议：

- `feat/xxx`
- `fix/xxx`
- `docs/xxx`
- `refactor/xxx`

commit message 示例：

- `feat: add tutor agent`
- `docs: add phase nine guide`
- `chore: update environment check`

## 后端规范

- 路由放在 `app/routers/`。
- 业务流程放在 `app/services/`。
- 智能体逻辑放在 `app/agents/`。
- Pydantic schema 放在 `app/schemas/`。
- 不要在 `main.py` 堆业务逻辑。
- Agent 输出需要记录 `AgentRun`。
- LLM 调用需要记录 `LLMCallLog`，不能记录 API Key。

## 前端规范

- 页面放在 `apps/web/app/`。
- API 封装放在 `apps/web/lib/api.ts`。
- 类型定义放在 `apps/web/lib/types.ts`。
- 组件优先复用现有 shadcn/ui。
- 不引入 axios、react-query、复杂状态管理、图表库或 AI SDK。

## 第九阶段边界

TutorAgent 可以：

- 接收课程相关问题。
- 检索 `DocumentChunk`。
- 结合学习画像、学习路径 step 和已生成资源作为上下文。
- 生成带 citations 的回答。
- 保存 `TutorSession` 和 `TutorMessage`。
- 通过 CitationVerifier 输出 `grounded`、`needs_review`、`unsafe`。

TutorAgent 不做：

- 学生答题提交。
- 自动批改。
- 学习效果评估。
- 掌握度自动更新。
- 学习路径动态调整。
- 真实外部模型调用。

## 数据与版权

- 不提交本地 SQLite 数据库。
- 不提交上传目录。
- 不上传出版教材 PDF、扫描件、电子书或教材原文。
- 示例课程资料必须是团队原创整理内容。
- 面对“复制教材原文”等请求，系统必须拒绝或提示版权边界。

## 第十阶段开发规范补充

PracticeAgent 和 EvaluatorAgent 的边界：

- PracticeAgent 只负责生成原创练习题，不提交答案、不批改。
- EvaluatorAgent 只负责自动批改、错因分析、掌握度更新和报告生成。
- SQL 实操题只做静态关键词评分，不执行学生 SQL。
- 不引入真实大模型 SDK、LangChain、ChromaDB、embedding、Redis、Celery 或图表库。
- 不复制教材原文，不处理教材 PDF 或扫描件。

前端规范：

- `/practice` 和 `/analytics` 继续使用 `useState` 和现有 API 封装。
- 不使用 axios、react-query、zustand、echarts、chart.js。
- 掌握度、准确率和评估结果用 Card、Badge、Progress、列表展示即可。

提交前检查：

```powershell
python scripts/check-env.py
.\scripts\check-phase10.ps1
```
# Phase 11 开发规范补充

演示工作台边界：

- `/api/demo/status` 只做状态聚合，不调用 LLM。
- `/api/demo/bootstrap` 只准备基础演示数据，不生成画像、路径、资源、辅导、测验或评估。
- `/demo` 只展示状态、下一步建议和跳转入口，不自动触发生成类接口。
- Spark 模式是允许状态，不应显示为错误，但要提示手动生成会调用真实 API。
- 前端不得显示、输入、传输或保存 APIPassword。

提交前检查：

```powershell
python scripts/check-env.py
.\scripts\check-phase11.ps1
```

## Phase 12 开发规范补充

- `/api/qa/checklist` 只返回人工测试项，不触发生成类操作。
- `/api/qa/smoke-status` 只读取数据库和配置，不调用 LLM、不调用 Spark、不修改数据库。
- `/qa` 页面只做人工检查和本地勾选，不自动跑测试，不自动调用生成接口。
- Spark 模式下，高消耗或批量生成操作要有清晰提示；真实模式不是错误状态。
- 前端不得显示、输入、传输或保存 APIPassword。
- 不新增图表库、复杂状态管理、Agent、真实外部 API 类型或交付材料。

Phase 12 一键检查：

```powershell
.\scripts\check-phase12.ps1
```

## Phase 13 开发规范补充

- 只做端到端彩排、API 命名一致性检查、低风险 bug 修复和体验补漏。
- 不新增 Agent，不新增真实外部 API 类型，不做 Docker、登录或最终交付材料。
- `/demo`、`/qa`、bootstrap 和 smoke-status 不得自动调用 LLM 或 Spark。
- 资源生成 API 命名统一使用 `/api/generated-resources/*`，不要回退到旧的 `/api/resources`。
- 页面和接口响应只显示模型模式、provider 和 model，不显示或传输真实密钥。

Phase 13 一键检查：

```powershell
.\scripts\check-phase13.ps1
```

## Phase 14A 开发规范补充

- 学生端页面优先使用学习语言，减少 Agent、Phase、Mock、Router 等工程词作为主视觉。
- `/learn` 是学生主入口，学习数据必须来自后端 API，不把核心学习状态放入 localStorage。
- Markdown 内容统一通过 `MarkdownPreview` 渲染，Mermaid 代码块统一通过 `MermaidDiagram` 渲染。
- Mermaid 使用客户端渲染和 strict security，失败时回退显示源码，不让页面白屏。
- 资源、辅导、练习和评估页面要优先展示中文状态、引用来源、进度条和学习建议。
- 顶部导航和侧边导航必须根据当前路径高亮，学习中心优先，演示/测试/管理入口降级。
- 不新增 Agent、数据模型、真实 API 类型、图表库、复杂状态管理或最终交付材料。
- 不读取、显示、传输、保存或提交真实密钥。

Phase 14A 一键检查：

```powershell
.\scripts\check-phase14a.ps1
```
