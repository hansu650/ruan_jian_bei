# 开发规范

本文档用于约定 EduForge 智学工坊项目的基础协作规范。当前项目处于第五阶段：MockLLM 与讯飞接口预留。

## 分支命名规范

- `feat/xxx`：新功能
- `fix/xxx`：问题修复
- `docs/xxx`：文档更新
- `refactor/xxx`：重构

示例：

```text
feat/course-crud
fix/api-health
docs/environment-guide
refactor/router-structure
```

## Commit Message 建议

使用清晰简短的英文前缀：

```text
feat: add health check
docs: add environment guide
chore: initialize project structure
feat: add sqlite crud foundation
fix: repair api startup script
```

## Python 代码规范

- 使用类型注解。
- 保持函数短小，避免单个函数承担过多职责。
- `main.py` 只负责创建 FastAPI app、配置中间件、注册路由和 lifespan。
- API 路由按业务域放到 `app/routers/`。
- Pydantic/SQLModel schema 放到 `app/schemas/`。
- 数据库模型放到 `app/db/models.py`。
- 数据库连接、session 依赖和初始化放到 `app/db/database.py`。
- seed 数据放到 `app/db/seed.py`。
- 后续复杂业务逻辑再放到 `services` 或 `agents`，不要提前堆入 router。
- 使用 `ruff` 做风格检查，使用 `mypy` 做基础类型检查。

## FastAPI 路由规范

- 路由统一使用 `/api` 前缀。
- 找不到资源时返回 404。
- 第三阶段只做 GET 和 POST，不做 PUT/PATCH/DELETE。
- 不在 CRUD 路由里实现 AI 生成、RAG、Agent、登录或权限逻辑。
- 创建接口使用 `XxxCreate` schema，返回接口使用 `XxxRead` schema。
- 不直接把数据库 table model 暴露为 POST 输入。

## SQLModel 与数据库规范

- 第三阶段使用 SQLite + SQLModel。
- 数据库文件默认生成在 `apps/api/eduforge.db`，不提交 Git。
- 所有表显式设置 `__tablename__`。
- `created_at` 和 `updated_at` 使用 UTC 时间默认值。
- JSON 字段本阶段先用字符串保存，不使用复杂 JSON column。
- seed 数据必须可重复运行，不能无限重复插入相同默认数据。
- 第三阶段不使用 Alembic，后续需要迁移能力时再评估。

## 课程资料与知识库规范

- `data/sample_courses/database_system/` 只存放团队原创整理的 Markdown 资料。
- 不提交出版教材 PDF、扫描件、电子书、出版社配套资料或教材原文摘录。
- 第四阶段只支持 `.md` 和 `.txt`。
- 上传文件保存到 `apps/api/storage/uploads/`，不提交 Git。
- 文档解析、分块、入库和检索逻辑放在 `app/services/`。
- `CourseDocument` 保存文档元数据，`DocumentChunk` 保存文本分块。
- `DocumentChunk` 不保存 embedding，不保存 vector。
- 当前关键词检索不是 RAG，不调用大模型。

## LLM Provider 规范

- 第五阶段只实现 Provider 抽象、MockLLMProvider 和 SparkProvider 预留。
- MockLLMProvider 不调用外部服务，固定输出用于演示和测试。
- SparkProvider 只返回预留说明，不读取、不打印、不发送真实密钥。
- 不新增 OpenAI-compatible Provider。
- 不引入 LangChain、OpenAI SDK、ChromaDB、sentence-transformers、torch。
- LLMCallLog 只保存 prompt 和 response 的 500 字以内预览。
- 不在日志、响应或文档中输出 API Key。
- Provider 层不实现 Agent、学习画像生成、学习路径生成或资源生成业务。

## TypeScript 代码规范

- 使用 TypeScript，避免使用 `any` 逃避类型设计。
- 页面级组件负责组合，通用展示组件放到 `components/`。
- API 请求封装在 `lib/api.ts`。
- 类型定义放到 `lib/types.ts`。
- 静态常量放到 `lib/constants.ts`。
- 不引入复杂状态管理库。
- 不引入认证库、AI SDK、图表库等当前阶段不需要的依赖。

## 前端目录规范

- `app/`：页面和路由。
- `components/`：项目展示组件。
- `components/ui/`：shadcn/ui 基础组件。
- `lib/api.ts`：前端 API 请求封装。
- `lib/constants.ts`：静态常量。
- `lib/types.ts`：前端类型定义。
- `lib/utils.ts`：通用工具函数。

## 组件命名规范

- React 组件文件使用 kebab-case，例如 `health-status-card.tsx`。
- 组件函数使用 PascalCase，例如 `HealthStatusCard`。
- 页面组件保持轻量，复杂展示拆到 `components/`。
- shadcn/ui 基础组件不要混入业务逻辑。

## Tailwind 使用规范

- 保持页面简洁、稳定、适合比赛演示。
- 不使用远程字体和远程图片，避免演示环境网络不稳定。
- 不使用花哨动画库。
- 控制 class 长度，重复结构优先拆成组件。
- 文字不要溢出按钮、卡片或表单区域。

## shadcn/ui 使用规范

- 当前只保留基础组件，如 button、card、badge、separator、progress、alert、skeleton。
- 不要一次性添加大量 shadcn 组件。
- 新增组件前确认页面确实需要。
- `components/ui/` 尽量保持接近 shadcn 标准写法。

## 环境变量规范

- 使用 `.env` 保存本地配置。
- 仓库只提交 `.env.example`。
- 不提交真实 `.env`。
- 新增环境变量时同步更新 `.env.example` 和相关文档。

## API Key 规范

- 不允许提交真实 API Key。
- 不允许在日志中输出 API Key。
- 不允许把 API Key 写死在源码、测试、README 或演示脚本中。
- 本阶段不接入真实大模型 API。

## 数据文件规范

- 不提交本地 SQLite 数据库文件。
- 不提交 `.chroma` 向量库持久化目录。
- 示例课程资料后续放入 `data/sample_courses/`，需要保证可公开、可复现。
- 大文件或模型文件进入仓库前必须先评估必要性。

## AI Coding 使用规范

- 可以使用 Codex 辅助生成代码、文档、测试和脚本。
- 生成后必须人工 review，确认逻辑、依赖、边界条件和安全性。
- 关键业务逻辑必须由团队确认，尤其是学习画像、多智能体协作、测验评估和防幻觉策略。
- 不要让 AI 一次性生成过大变更，按阶段拆成小任务。
- 比赛文档中需要说明使用过的 AI Coding 工具、使用范围和团队自主开发部分。

## 第六阶段开发规范补充

- ProfileAgent 只负责画像抽取和画像更新，不要在本阶段实现 PlannerAgent、ResourceAgent、TutorAgent 或完整多智能体编排。
- `main.py` 只 include router，不堆画像业务逻辑。
- 画像相关业务放在 `app/services/profile_service.py`，轻量 Agent 逻辑放在 `app/agents/profile_agent.py`。
- `LearnerProfile` 中的 list/dict 字段当前用 JSON 字符串保存，不引入复杂 JSON column。
- 前端 `/profile` 页面用 `useState` 和现有 shadcn/ui 组件即可，不引入 react-query、zustand、图表库或表单库。
- AgentRun 和 LLMCallLog 只保存预览，不保存 API Key 或超长敏感输入。

- 文档要说明团队自主开发部分。
- 不抄袭历届项目代码，不使用来源不明的业务代码。
- 演示视频控制在 7 分钟内，突出 A3 题面要求与 EduForge 的闭环价值。
- PPT、系统开发说明书、测试说明书和运行说明要与最终代码保持一致。
