# Phase 15A：学生端 UI 升级与创新点包装

## 1. 本阶段目标

Phase 15A 继续使用 EduForge 自己的代码体系，不切换项目、不复制其他作品代码或页面。本阶段主要做产品化 UI 和竞赛表达升级：

- 强化 `/learn` 学生学习工作台。
- 新增 `/agents-flow` 多智能体协作流程视图。
- 新增 `/innovation` 创新亮点页。
- 优化首页、导航和核心学习页面的产品表达。
- 将真实已有能力包装成评委容易理解的亮点。

本阶段不新增 Agent、不新增后端大功能、不新增真实外部 API、不生成最终交付材料。

## 2. 为什么要做学生端 UI 升级

前面的阶段已经完成画像、路径、资源、辅导、测验和评估等核心能力，但页面更偏功能集合。比赛演示需要让评委和学生一眼看懂：

- 学生从哪里开始。
- 今天应该学什么。
- 系统为什么推荐这一步。
- 多个智能体如何协作。
- 项目相比普通聊天机器人有什么亮点。

因此 Phase 15A 将页面从“功能模块展示”推进到“学习旅程表达”。

## 3. `/learn` 学习工作台设计

`/learn` 是学生端主入口，展示：

- 当前学生和课程。
- 学习目标。
- 当前状态，例如正在补齐 JOIN、事务隔离级别、B+ 树索引等薄弱点。
- 今日推荐学习步骤。
- 预计用时和相关知识点。
- 学习进度概览。
- 我的薄弱点和掌握度。
- 学习旅程：画像、路径、资源、辅导、测验、评估。

这些数据来自后端 API 和数据库，不存放在 localStorage。

## 4. `/agents-flow` 多智能体协作视图

`/agents-flow` 用于解释 EduForge 的轻量多智能体流水线：

- `ProfileAgent`：从学生对话中生成 8 维学习画像。
- `PlannerAgent`：根据画像和课程知识点生成学习路径。
- `ResourceAgent`：围绕学习步骤生成 6 类资源。
- `TutorAgent`：基于课程知识库回答问题并展示引用来源。
- `PracticeAgent`：生成多题型测验。
- `EvaluatorAgent`：自动批改、分析错因、更新掌握度并生成评估报告。
- `CitationVerifier`：检查引用来源和版权风险。

页面明确说明当前是自研轻量 Agent 流水线，不宣称接入 CrewAI、LangGraph 或复杂调度平台。

## 5. `/innovation` 创新亮点页

`/innovation` 只包装真实已实现能力：

1. 画像驱动的个性化学习闭环。
2. 可信课程知识库与引用来源。
3. 多智能体学习流水线。
4. 六类个性化学习资源生成。
5. 轻量掌握度追踪与学习效果评估。
6. Mock / Spark 双模式。
7. 引用来源防幻觉与版权边界。

页面同时列出“不虚假宣传边界”，避免把未实现的功能写成已完成。

## 6. UI 风格调整

Phase 15A 保持清爽、可信、学生端学习产品风格：

- 主色使用低噪音蓝色。
- 顶部导航只保留核心学习入口。
- 架构、亮点、演示、测试和管理入口放到侧边栏。
- 卡片使用白底、细边框、轻阴影。
- 主按钮指向下一步学习行动。
- 学生端页面减少 AgentRun、LLM、API、Phase 等工程词。

## 7. 不抄 EduAgent，只借鉴表达方式

本阶段参考的是“优秀参赛作品如何表达功能”的方式，例如：

- 需求映射。
- Agent 分工。
- 页面架构表。
- 创新点命名。

EduForge 不复制其他作品代码、页面、文案、配色或图片。

## 8. 真实实现的创新点

当前可以真实展示：

- 对话式 8 维学习画像。
- 画像驱动路径、资源、测验和评估。
- 原创《数据库系统》课程资料和知识库检索。
- 资源与辅导回答的 citations_json。
- 多 Agent 学习流水线。
- 自动批改、错因分析、掌握度更新和评估报告。
- Mock / Spark Lite 双模式。

## 9. 未实现功能不虚假宣传

当前不宣称已经实现：

- 完整 BKT 算法。
- 情感识别。
- 费曼学习法。
- 多 Agent 对抗辩论。
- 成就系统。
- 知识图谱可视化。
- CrewAI / LangGraph 调度平台。
- 流式输出。
- 内置真实 API Key。

轻量掌握度追踪可以作为后续扩展为 BKT 的基础，但不能写成完整 BKT 已实现。

## 10. 验收方式

自动检查：

```powershell
.\scripts\check-phase15a.ps1
```

```bash
./scripts/check-phase15a.sh
```

人工检查重点：

1. `/` 是否像正式产品首页。
2. `/learn` 是否像学生学习首页。
3. `/agents-flow` 是否清楚展示多个 Agent 的协作链路。
4. `/innovation` 是否只写真实创新点。
5. `/resources` 是否继续正常渲染 Markdown / Mermaid。
6. `/tutor` 是否中文化可信状态和引用来源。
7. `/practice` 是否更像练习反馈。
8. `/analytics` 是否更像学习诊断结果。
9. 导航是否以学习入口优先，辅助入口降级。
10. 页面、文档和日志中没有 APIPassword。
