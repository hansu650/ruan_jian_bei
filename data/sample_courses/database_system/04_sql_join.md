# JOIN 与子查询

## 学习目标

学习本节后，你应该能够解释 INNER JOIN、LEFT JOIN、RIGHT JOIN 的差异，理解连接条件在多表查询中的作用，能读懂常见子查询，并能判断 JOIN 和子查询各自适合的场景。你还需要能识别多表查询中常见错误，例如忘记连接条件导致结果暴增。

## 核心概念

JOIN 用于把多张表中相关的行组合起来。INNER JOIN 只保留两边都匹配的行；LEFT JOIN 保留左表全部行，右表没有匹配时用 NULL 补齐；RIGHT JOIN 与 LEFT JOIN 方向相反，保留右表全部行。连接条件通常写在 ON 后面，例如 `course.id = knowledge_point.course_id`。

子查询是在一个 SQL 中嵌套另一个查询。它可以出现在 WHERE、FROM 或 SELECT 中。比如先查出“数据库系统”的课程 id，再用这个 id 查询知识点。子查询表达直观，但复杂场景下可能不如 JOIN 清晰。JOIN 更适合展示多表字段，子查询更适合表达“满足某个集合条件”的过滤。

## 示例说明

如果要查询每个知识点所属课程名称，可以把 course 表和 knowledge_point 表连接起来：课程表提供 title，知识点表提供 chapter、summary 和 difficulty。INNER JOIN 会返回已有课程且已有知识点的记录。如果想显示所有课程，即使某门课程还没有知识点，也可以用 LEFT JOIN 从 course 出发。

在学习平台中，JOIN 常用于“课程 + 知识点”“学生 + 画像草稿”“资源占位 + 知识点标题”等组合展示。子查询可以用于“找出属于数据库系统课程的所有资源”“找出包含某个薄弱点学生相关的画像草稿”等过滤。

## 常见误区

多表查询最常见错误是漏写连接条件。如果 course 有 3 行，knowledge_point 有 10 行，漏掉 ON 条件可能得到 30 行组合，这种笛卡尔积通常不是业务想要的结果。另一个错误是把 WHERE 条件写错位置，导致 LEFT JOIN 退化成类似 INNER JOIN。例如右表字段在 WHERE 中要求非空，就会把原本没有匹配的左表行过滤掉。

还要注意 JOIN 和子查询不是简单的谁更高级。JOIN 适合把多表字段合在一起展示；子查询适合先确定一个集合，再用集合过滤外层查询。实际开发中应优先选择可读、可维护、能被数据库优化的写法。

## 练习提示

请思考以下问题：如何查询《数据库系统》课程下所有知识点？如何查询每个课程的知识点数量？如果想显示没有知识点的课程，应该使用 INNER JOIN 还是 LEFT JOIN？尝试解释为什么连接条件写错会导致结果数量异常增多。
