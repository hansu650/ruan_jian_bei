# 综合复习

## 学习目标

本节用于把数据库系统的核心内容串联起来，帮助你从“概念散点”过渡到“知识网络”。复习后，你应该能够说明数据库基础、关系模型、SQL、JOIN、ER 建模、范式、事务、索引和查询优化之间的联系，并能根据题目类型选择合适的解题思路。

## 核心概念

数据库系统课程可以按三条线索复习。第一条是数据建模线：从业务场景出发，识别实体、属性和联系，画出 ER 模型，再转换为关系表，并用主键、外键和约束保证基本一致性。第二条是数据操作线：使用 SQL 查询、插入、更新和统计数据，掌握 JOIN、子查询、分组和排序。第三条是系统机制线：理解事务隔离、索引结构、查询优化和并发控制。

这些内容不是孤立的。ER 建模决定表结构，表结构影响 SQL 写法；范式帮助减少冗余，但查询性能可能需要索引支持；事务保证并发修改安全，索引和执行计划影响查询速度；知识库系统中的文档 chunk 也需要数据库表保存来源、顺序和内容摘要。

## 示例说明

复习“数据库系统”时，可以用 EduForge 项目本身作为贯穿案例。Student、Course、KnowledgePoint 是关系模型和 ER 建模的例子；ProfileDraft 展示了学生与课程之间的学习状态；CourseDocument 和 DocumentChunk 将在知识库阶段保存课程资料和文本分块；搜索功能体现了基础查询和来源追踪。

如果考试题要求解释幻读，你应先定位到事务与并发控制，再说明它是范围查询下行集合变化的问题。如果题目问 B+ 树为什么适合索引，应从磁盘页、低树高、有序叶子节点和范围查询入手。如果题目给出多表查询错误结果过多，应优先检查 JOIN 连接条件。

## 常见误区

复习时不要只背定义。数据库题目常要求结合场景判断，例如“是否需要拆表”“某个隔离级别是否足够”“某个索引是否有效”。另一个误区是把 SQL 题当作字符串拼接题，而忽略数据含义。写 SQL 前应先画出涉及哪些表、表之间怎样关联、过滤条件属于哪张表。

也不要把性能优化和正确性混在一起。正确性优先解决数据含义、约束和事务问题；性能优化再考虑索引、执行计划和缓存。一个结果错误但运行很快的查询没有价值。

## 练习提示

请按照“建模、查询、机制”三条线整理自己的复习清单。对每个知识点写下一个典型问题，例如 JOIN 的典型问题是连接条件，范式的典型问题是更新异常，事务的典型问题是并发异常，索引的典型问题是查询是否能命中 B+ 树索引。最后用项目中的《数据库系统》知识库尝试搜索“幻读”“B+树”“JOIN”，观察来源片段如何帮助复习。
