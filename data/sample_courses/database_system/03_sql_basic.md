# SQL 基础

## 学习目标

学习本节后，你应该能够读懂并编写基本 SQL，包括 SELECT、WHERE、ORDER BY、LIMIT、INSERT、UPDATE、DELETE，以及常见聚合函数和 GROUP BY。你还需要理解 SQL 是声明式语言：我们描述想要什么结果，数据库负责选择执行方式。

## 核心概念

SQL 可以分为数据查询、数据定义、数据操作和数据控制等类别。本阶段重点关注查询和基本增删改。SELECT 用于指定输出列，FROM 指定数据来源，WHERE 过滤行，ORDER BY 排序，LIMIT 控制返回数量。聚合函数如 COUNT、AVG、SUM、MAX、MIN 用于汇总数据，GROUP BY 用于按某些字段分组统计。

SQL 的执行结果是表状结果，但它不等于按书写顺序逐行执行的脚本。初学时可以按“先确定数据来源，再过滤，再分组，再选择输出，再排序”的思路理解。WHERE 用于过滤原始行，HAVING 用于过滤分组后的结果。NULL 表示未知或缺失，不能简单等同于空字符串或 0。

## 示例说明

假设 Course 表保存课程，KnowledgePoint 表保存知识点。查询全部课程可以写成 `SELECT * FROM course;`。如果只想看计算机科学相关课程，可以增加 `WHERE subject = '计算机科学'`。如果要统计每门课程有多少知识点，可以按 course_id 分组并使用 COUNT。

在学习平台中，SQL 不只是“查表工具”。后续系统需要根据学生薄弱点筛选知识点，根据课程统计资源数量，根据画像草稿查询某学生的学习目标。即使未来接入大模型，底层可靠的数据查询仍然是系统稳定运行的基础。

## 常见误区

常见误区之一是滥用 `SELECT *`。在开发和调试时它很方便，但正式接口更应该选择需要的列，避免返回过多数据。另一个误区是忘记 WHERE 条件，尤其在 UPDATE 和 DELETE 时风险很高。本项目第三阶段暂不提供删除接口，就是为了降低演示阶段误删数据的概率。还有同学会误把 NULL 与 `=''` 混用，导致查询不到预期结果。

聚合查询也容易出错。使用 GROUP BY 时，SELECT 中非聚合列通常应出现在 GROUP BY 中，否则结果含义不清。HAVING 不是 WHERE 的替代品，它用于分组后的过滤。例如“知识点数量大于 5 的课程”应先分组统计，再用 HAVING 过滤。
